# 两张模板表的对照

> P4 的价值不是"多存一张表",是**证伪**:两张放在一起,才知道"模板表"这个抽象
> 是不是真的成立,还是只是第一册的形状被当成了通式。
> 量于 2026-08-15,第二册(八年级物理暑假班)走通之后。

## 量出来的

拿两张**完整工作 schema** 比(不是拿蒸馏过的种子比完整表——那是不公平的比法,
第一次我就比错了,得出"只有 7/30 共有"的假结论)。

| | 化学(沪科版) | 物理(暑假班) |
|---|---|---|
| 顶层键(去注释键) | 22 | 21 |
| 角色数 | 20 | 13 |
| 共有键 | 11 | |

**共有的 11 个**——这就是抽象真正成立的部分:

```
roles  optionMarkers  sectionBanners  calloutHeads  tags  subModules
questionNumberRegex  embeddedObjects  fieldRenderings  diagnostics  schemaVersion
```

## 差异的三种性质,只有一种是抽象的问题

不能把 21 个不共有的键笼统算成"抽象不成立"。它们性质不同,处置也不同。

### 一、学科特性(化学有、物理没有)—— **这一类是抽象的真实边界**

```
reactions  conditionArrows  shapeArrows  chartSubstitutions  vectorFigureSubstitutions
```

化学要把箭头转成反应式结构,物理不需要。这是真差异,**不该硬统一**。
处置:承认模板表有"学科扩展段",核心段通用、扩展段按学科声明。
本轮已验证扩展段是安全的——化学的反应抽取在物理源上跑过,0 转换、12 次正确拒绝。

### 二、这一册恰好没用到(化学有、物理没用)—— **不是差异,是覆盖不全**

```
bannerSlots  listProperties  tableProperties  embeddedObjectPolicy
nativeTextSubstitutions  openItems
```

物理册不是"不需要"这些,是这一批 5 讲没撞上。第三册很可能要用。
处置:留在通用段,别因为第二册没用就删——那会让第三册重新发明一遍。

### 三、第二册新长出来的治理字段(物理有、化学没有)—— **这是版本滞后,不是分歧**

```
fingerprint  provenance  status  retiredRoles  sourceDefects  hierarchy  runMarks  id
```

这八个全是本轮为了堵已发生的坑加的:判据恒假要 `retiredRoles` 记录、
册级色值要 `runMarks`、层级词表要 `hierarchy`、每条规则要 `provenance` 带出处。
它们与学科无关,**化学表也该有,只是当时还没有**。

处置:**回填到化学表**,而不是当成两张表的分歧。
不回填的后果很具体——第三册建表时会照着两张不一致的范例,
挑哪张全看运气。

## 结论

抽象**成立**,但它的形状不是"一张扁平的表",是:

```
核心段(11 键)      ← 通用,两册一致,可作范例
学科扩展段         ← 按学科声明,不硬统一(化学反应式是真需求)
治理段(8 键)       ← 通用,但第一册还没有,应回填
覆盖不全的部分     ← 留着,别因为一册没用就删
```

一句话:**第二册没有推翻模板表,它推翻的是"模板表只有一层"。**

## 待办(P4 留下的)

| | |
|---|---|
| 治理段回填化学表 | 8 个键。不做则第三册照着两张不一致的范例建表 |
| 种子表自足性 | `seeds/templates/*.json` 目前不够指纹比对用,还得另找完整 schema(见 steps.v1.json 的 `schema.reference`)。种子本该自带指纹判据 |
| 核心/扩展/治理三段的显式分段 | 现在是我人眼分的,表里没有字段标明某键属于哪一段。第三册之前应做成数据,否则每次都要重新判断 |
