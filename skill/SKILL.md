# 讲义入库

把一份或一批 Word 变成两个产物：

1. **原子化的内容** —— 语义块 + 归属 + 来源，每块可回指源文件哪一段
2. **私有规范的编制成品** —— 规范文档 + 参数表，每个值带归属与原文引用

**规范是产物，不是输入。** 没有现成规范时，从源文件观测出版式事实，对照标准模板
判定哪些是硬底线、哪些是可选，其余列为待裁决。

---

## 这是方法，不是范例集

`seeds/` 里的国标参数模板、沪科版模板表、本册示例，都是**样例**，可以整份替换。
遇到新出版社、新学科、新标准，走的是同一套方法，长出来的是新的表。

## 九步

```
0 画「事实住在哪」  ← 最先做，半小时
1 块型普查          → 对象类全集
2 矩阵：对象类 × 视角，每格判保证来源，空白必须写出来
3 建门框架（含引文门）
4 写规则，每条带门、每个常数带原文出处
5 渲染成品，人眼过一遍
6 每个发现先扫全类，再动手
7 每关一格升级为「有门」，并做破坏性自证
8 定稿后，本次裁决按本质归纳
```

### 第 0 步为什么排最前

把事实的流转链画出来，每一跳列出谁持有哪些事实：

```
标准 → 私有规范 → 参数表 → 引擎 → 成品
```

**凡是同一事实在两处出现，当场记为「待加断言门」。** 不要等它出事。

首册漏了这一步，六处漂移一起爆发（规范内部自相矛盾、参数表两个值并存、
规则与判据两套口径、脚本两条解析规则……），而当时二十项审计、九步流程、
三道门**全部通过**。

### 四条前置纪律

1. **说「不知道」之前，先读完手边写着答案的文件。** 首册 61 个「不知来源」的参数，
   大半来源一直躺在私有规范里，而且多数是国标。
2. **门先建，而且拿「有病的成品」建。** 首册三道新门全都在第一次运行时抓到了自己的
   毛病。先修再建门，门会带着毛病一直绿。
3. **每个筛子上线时证明它命中过。** 判据恒假不产生错误输出，只产生沉默。
4. **凡是要写进文档或告诉人的数字，先跑一次再写。**

## 与人确认：按类问，不按个问

**人眼定类 → 扫全量定量 → 门定复发。**
首册实测：1 处报告 → 22 处实际、1→5、1→18、1→39。

> 「发现 39 处单元格里的列表被平铺。**是不是都该保留分行？**」
> 而不是问 39 遍。

真正需要人的只有四类：

| | 问题 | 为什么机器判不了 |
|---|---|---|
| 1 | 这张图/表是不是本该是文字 | 位图里有字很常见，有字不等于该转；要看着想「这块内容的正确形态是什么」 |
| 2 | 源缺陷是**笔误**还是**漏做** | 决定逐条覆盖还是做成模式，处置相反 |
| 3 | 偏离规范是接受还是回改 | 取决于使用方的取舍 |
| 4 | 版面取舍的标价 | 留白值不值，是审美与成本的判断 |

**认不出的一律进复核队列，不猜。** 所有门都是「宁可拒绝，不可猜」：
注册了没匹配上就抛异常、读不到规则就报错、算不出就报 NULL 加原因。
放松这一条，「越来越好用」会变成「越来越多沉默的错误」。

## 成长：写进 `<workspace>/.handout-intake/` 的东西必须过判据

**成长不是「随便写进去」。** 每条规律必须带：

| 字段 | 要求 |
|---|---|
| 现象 / 判据 / 处置 / **本质** | 四元组，**聚类键是本质，不是现象** |
| 全类扫描 | 命中几处。1→1 先挂在 `transient/`，不升格 |
| 门 | 配不出门的只能记为观察，不能记为规律 |
| 自证 | 破坏性验证做过没有 |
| 认可状态 | 定稿前一律 `provisional` |

### 升格四判据

1. 有没有**确定的形状**（能写成模式而不吃到别的东西）
2. 扫全类后**命中几处**
3. 能不能**配一道门**
4. **破坏性自证**过不过

第 1 条最易错：**表面同类、本质相反**。「多余的句号」与「漏标出处颜色」都是源缺陷，
一个是笔误（一次写错，无形状 → 逐条覆盖），一个是漏做（同一件事没做全，有形状 →
做成模式 + 计数）。

### 时序：定稿之后才挖规律

```
执行期  →  按现有样例做，不确定的问人，记下每个裁决及其依据
定稿期  →  使用方审核通过，本册裁决标记为「已认可」
挖掘期  →  只在已认可的集合上找规律
```

在认可之前归纳，会把错的选择变成**带门的规则**——从此复发更快、更难发现。

### 被否掉的调查也要记

否定结论是最容易丢、也最省时间的那部分。不记，下一册会有人从头再查一遍。
记进 `transient/`，状态 `rejected`，写明**下次省什么**。

---

## 长期规则要带命中统计

规则一旦进长期记忆就没人再质疑。每条记**上线以来命中次数**：
长期为 0 先怀疑**判据恒假**，不是「确实没有」。

首册实例：一个分支写在与它互斥的过滤之后，从写下那天起就到不了，报的 0 从来不是真的。

## 能力分级

| 能力 | 依赖 | 没有依赖时 |
|---|---|---|
| 原子化、私有规范编制、全部门、矩阵、登记册 | 纯 Python | **都能用** |
| 出 Word 母版 / PDF / 装订 / 文字转曲 | Word + Acrobat（macOS） | **降级**：仍产出上面两个产物，不产出印刷件 |

没有 Word 的使用者照样拿得到那两个产物。**不要因为出不了 PDF 就整条流程拒绝运行。**

## 与外部基础设施的关系

如果工作区已有脚本治理预检、产物哈希绑定、协调账本这类设施，**用它们，不要在
skill 里重建**——重建就是复制，正是这套方法要消灭的东西。
没有时降级运行，并在报告里写明「本次未经过 X 门」。

## 开始一次任务

1. `method/scripts/init_workspace.py --workspace <路径>` 建成长目录
2. 指纹识别：这批 Word 像不像已知模板？像 → 用那张表；不像 → 走建表流程
3. 按九步做
4. 定稿后运行归纳，把够格的规律升格

**每一步的产出都要能回答同一个问题：这个结论是量出来的，还是我以为的。**
